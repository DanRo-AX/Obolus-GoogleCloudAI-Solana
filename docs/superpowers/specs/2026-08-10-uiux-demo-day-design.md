- 날짜: 2026-08-10
- 결정자: Dan
- 렌즈: ① 데모데이 시연 동선 ② 실사용 마찰 제거 (전면 감사를 기점으로 우선순위 도출)
- 확정 사항: **데모데이 시연은 한국어로 한다.** 접근은 A안(마찰 먼저, 순차).

## 배경 — 감사에서 확정된 문제

로컬 스택(시드 데모 데이터)을 실제로 돌며 확인했다.

| # | 문제 | 근거 | 렌즈 |
|---|---|---|---|
| 1 | 대시보드 배너가 KO 모드에서 영어로 샌다 | `Dashboard.tsx:591`의 `t('Your account is ready…')` 키가 `ko.ts`에 없음 | 마찰 |
| 2 | 내 질문 상대시간이 항상 영어("20m ago") | `Archive.tsx:268-270`이 `t()` 없이 하드코딩. Dashboard(984-987)는 번역 키 사용 — 불일치 | 마찰 |

랜딩·내 서가(빈 상태)·온보딩 구조는 시연 품질이 이미 좋다. 결제 순간 Phantom
"Unknown" 안내는 2026-08-10에 별도 구현 완료(Chat.tsx confirm 카드).

## Phase 1 — i18n 정합 + 마찰 제거 (프론트만)

1. **i18n 전수 스캔**: `src/`의 `t('…')` 리터럴을 추출해 `ko.ts` 키셋과 대조하는
   일회성 스크립트(`scripts/i18n-audit.mjs`). 누락 키 전부 보완. t() 미적용
   하드코딩 영어(상대시간 등)는 grep 병행 검출.
2. **Archive 상대시간**을 Dashboard 방식(번역 키)으로 통일.
3. **대시보드 프로필 게이트 정리**: 카드별 "프로필 만들기" 제거, 안내 배너 1곳 유지.
   카드 CTA는 "답하기"로 복원, 프로필 없으면 클릭 시 온보딩으로 유도.
4. **폴리시**: 태그 잘림은 ellipsis 유지 + `title` 툴팁으로 전문 노출(Chat의 민트
   축약 표기와 같은 관례), 온보딩 단계 표기 통일.

검증: `npm run build` + `npm run lint`, KO 모드로 전 라우트 순회하며 영어 누수
grep + 스크린샷 비교.

## Phase 2 — 시드 한국어화 (`backend/src/seed.rs`)

0. **리스크 게이트(필수 선행)**: 한국어 문서 1~2개를 임시 시드하고 한국어 질문
   resolve가 HIT되는지 검증한다. 랭킹은 word/char n-gram + 768차원 해시 임베딩이라
   한국어 매칭 품질은 검증 전까지 미지수다. 실패하면 여기서 멈추고 설계 재논의.
1. 페르소나·문서·공개 모집을 한국어로 재작성. 성수동 점심 시나리오 유지,
   BRIEF.md 합니다체 톤. 개인정보는 생활 수준(BRIEF 원칙).
2. 한국어 데모 질문 세트 문서화: HIT 3개, MISS 1개.

검증: `cargo test` 통과 + 실스택에서 데모 질문 전부 리허설.

## Phase 3 — 데모 리허설·리셋

1. DB 초기화→재시드 원커맨드(개발 모드는 시드 자동이므로 `openshelf.db` 삭제
   래퍼 수준).
2. 시연 계정 2개(질문자/답변자) 준비 절차 문서화. Phantom Devnet USDC 준비 포함.
3. E2E 대본(`obolus-e2e-대본.md`)에 한국어 질문 반영. 8/21 전 전체 동선 리허설 1회.

## 원칙

- 각 Phase는 독립 검증 후 다음으로. Phase 2 실패가 Phase 1 결과물을 되돌리지 않는다.
- 백엔드 로직(검색·결제·원장)은 건드리지 않는다. Phase 2도 시드 데이터만 바꾼다.
