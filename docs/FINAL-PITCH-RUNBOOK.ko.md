# Obolus 결선 발표 런북

기준일: 2026-08-11<br>
본편: 6분 안에 8장과 90초 라이브 데모 포함<br>
보조: 전체 20장, 질의응답용

## 발표의 단 하나의 목적

발표가 끝났을 때 심사위원은 Obolus를 “AI가 답을 생성하는 서비스”가 아니라,
**제한된 AI 루프가 필요한 인간 근거를 찾고, 사용자가 승인한 문서만 결제하고, 그 소유자에게
Solana USDC를 정산하는 검색 인프라**로 기억해야 한다.

발표자는 다음 세 문장을 반복해서 연결한다.

1. 검색은 무료이고 인간 원문만 유료다.
2. Gemini는 검색 전 metadata 계획과 검색 후 다음 제안 선택을 두 번의 함수 호출로
   수행하고, 동의·가격·문서 공개·결제는 결정론적 시스템이 강제한다.
3. 검색 실패는 빈 화면이 아니라 필요한 사람만 모집하는 Open Call이 된다.

## 무대 준비

발표 시작 10분 전 다음 네 화면을 순서대로 연다.

1. 탭 1, `docs/obulus-pitch-deck.html?mode=final`: 8장 심사 모드
2. 탭 2, 라이브 제품: 로그인과 지갑 연결을 끝낸 질문 화면
3. 탭 3, Solana Explorer Devnet: 데모 실행에서 열릴 새 탭
4. 탭 4, `artifacts/finalist-evidence/infrastructure.json`,
   `artifacts/finalist-evidence/autonomy.json`,
   `artifacts/finalist-evidence/devnet.json`: `summary.ready` 확인

탭 1에서 3번 슬라이드까지 말한 뒤 `Command/Ctrl+2`로 제품에 들어간다. 데모가
끝나면 `Command/Ctrl+1`로 덱에 돌아와 다음 장으로 진행한다. `B`는 덱 탭에서만
사용하며, 8장 모드의 마지막 증거 장으로 이동한다. 전체 20장으로 바꾸지 않는다.

발표 덱 단축키는 다음과 같다.

- `→`, `Space`: 다음 장
- `←`: 이전 장
- `6`: 8장 심사 모드와 전체 20장 전환
- `B`: 현재 모드의 마지막 증거 장으로 즉시 이동
- `Home`, `End`: 첫 장, 마지막 장

발표 노트북은 알림·자동 업데이트·화면 잠금을 끄고, 브라우저 확대율 100%,
16:9 출력, 유선 전원과 안정적인 네트워크를 사용한다. 질문과 유료 passage에는
개인식별정보를 넣지 않는다.

### 발표 당일 데모 카드

발표 24시간 전에 아래 값을 실제 사전 실행에서 채운다. 지갑 주소, 토큰, 원문과
개인식별정보는 이 문서에 기록하지 않는다. 값 하나라도 비어 있으면 온체인 HIT
성공 경로를 하지 않는다. 정적 UX 시나리오나 mock backend를 라이브 제품처럼
대체하지 말고, 통과한 증거 장과 남은 데이터 gate를 정확히 설명한다.

| 항목 | 발표 전 기록할 값 |
| --- | --- |
| 제품 URL과 배포 revision | 비밀이 아닌 URL·revision |
| 기업형 데모 질문 | 실제 고객 제공 질문이면 서면 사용 허가도 확인 |
| 실제 인간 문서와 사용 허가 | 작성자가 사실성을 확인하고 발표·유료 열람에 동의했는지 확인 |
| 기대 분기 | HIT, PARTIAL, MISS 중 하나 |
| 기대 후보·선택 문서 수 | 사전 실행에서 관찰한 수 |
| 기대 총액과 수수료 포함 여부 | quote의 atomic amount 합계 기준 |
| 로그인·지갑·선불 잔액 | 화면에서 준비 완료만 확인, 비밀값 기록 금지 |
| Devnet cluster와 Explorer 링크 | 반드시 Devnet 표시 확인 |
| 증거 run ID·query ID·job ID | 같은 실행을 연결하는 비민감 ID |
| 실패 전환 담당자 | 12초 경과를 알리고 탭 1로 복귀할 사람 |

## 90초 라이브 데모

성공 경로는 세 evidence JSON이 최신 schema와 revision 상관관계를 통과하고, 발표 URL의
Cloud SQL에 서면 사용 허가·본문 version hash가 연결된 실제 인간 문서가 있으며,
그 문서를 resolve → quote → open → payout → paid-only synthesis로 잇는 발표 당일 데모
카드가 완성됐을 때만 사용한다. fixture·mock backend·사전 녹화 화면은 이 조건을
충족하지 않는다. 세 JSON만 통과해도 각각 인프라·제한 자율성·Open Call 결제 capability를
증명할 뿐 HIT 통합 run은 아니다. 조건이 없으면 결제를 시도하지 않는다.

다음 네 값이 한 job으로 이어져야 데모 성공이다.

- 화면의 `queryId`와 `jobId`
- 문서별 quote 총액과 실제 transaction의 합
- Explorer signature와 데이터 소유자 USDC 증가
- 동일 job 재조회 뒤 `duplicateSettlementCount=0`

정상 HIT 경로와 별도로, `devnet.json`은 Open Call funding·payout 뒤 미사용 예약을
돌려주는 finalized refund receipt를 검증한다. 환불은 90초 HIT 화면에서 억지로
만들지 않고 별도의 typed Open Call lifecycle run으로 기록한다.

### 중단 기준과 복구 멘트

한 단계가 12초 넘게 멈추면 새로고침이나 재결제를 반복하지 않는다. 탭 1로 돌아와
`B`를 눌러 증거 장으로 이동한다.

- `infrastructure.json`, `autonomy.json`, `devnet.json`이 모두 `summary.ready=true`인 경우:
  “라이브 네트워크가 지연되어 제출용 capability 증거로 전환하겠습니다. 현재 serving
  revision의 두 단계 Vertex run과 별도 Open Call의 transaction·소유자 잔액·2-RPC
  finality·중복 지급 0·환불을 구분해 보여드리겠습니다. 이것을 HIT 동일 run이라고
  주장하지 않겠습니다.”
- 세 파일 중 하나라도 없거나 `ready=false`인 경우:
  “지금 보신 것은 코드 경로 데모이며 운영 완료라고 주장하지 않겠습니다. 현재
  통과한 범위와 남은 게이트를 정확히 보여드리겠습니다.”

샌드박스 receipt, fixture signature, 이전 실행의 무관한 Explorer 거래를 실제
라이브 증거처럼 사용하지 않는다.

## 예상 질문과 20초 답변

### “Gemini가 자율적으로 무엇을 합니까?”

첫 함수 호출은 질문에서 대상·지역·근거 수를 제한된 enum으로 보완합니다. Rust가
검색·랭킹한 뒤 두 번째 함수 호출은 aggregate HIT/PARTIAL/MISS를 보고 구매 제안,
부분 조사, Open Call, 무료 baseline, 종료 중 하나를 고릅니다. 서버가 결과와 맞지
않는 선택을 거부하고 지출 제안은 사용자 승인에서 멈춥니다. 별도 합성 호출은
결제된 근거만 받습니다. A2A나 독립 Agent 3개라고 주장하지 않습니다.

### “그냥 설문 플랫폼 아닌가요?”

설문은 매번 사람을 다시 모집하지만, Obolus는 기존의 동의된 답변을 먼저 검색하고
실제로 연 문서에만 지불합니다. 검색이 부족한 부분만 Open Call로 수집하고, 새
답변은 다음 질문에서 다시 검색·정산되는 자산이 됩니다.

### “블록체인이 왜 필요합니까?”

원문을 온체인에 올리기 위해서가 아닙니다. 여러 데이터 소유자에게 문서 단위로
소액 지급하고, 어떤 버전이 누구에게 얼마로 열렸는지 Agent가 검증 가능한
receipt를 남기기 위해 사용합니다. 원문은 오프체인에 남습니다.

### “결제가 답변의 진실성을 증명합니까?”

아닙니다. 결제는 문서 버전, 수취인, 금액과 접근 사실을 증명합니다. 진실성과
품질은 구체성, 중복 탐지, 독립 검증 관계, 작성자 이력과 구매자 피드백으로 별도
평가합니다.

### “사용자 지갑을 Agent에게 맡기는 것 아닌가요?”

Phantom은 지갑 소유 증명과 필요할 때의 제한된 충전만 서명합니다. Agent는 내부
선불 잔액과 질문별 최대 예산만 사용할 수 있고, Cloud KMS 운영 키와 로컬 Pay.sh
키도 각각 분리돼 원시 키가 모델에 들어가지 않습니다.

### “경쟁사가 복제하기 어려운 것은 무엇입니까?”

체인 연결 자체가 아니라, 동의된 인간 memory, 실제 검색 MISS, 독립 evidence
graph, paid reuse와 buyer outcome이 함께 축적되는 데이터·수요 루프입니다.

### “현재 가장 큰 미완성은 무엇입니까?”

현재 발표 리스크는 공개 Cloud SQL 서가에 사용 허가된 실제 인간 문서가 아직 없어
HIT 라이브 경로를 보장할 수 없다는 점입니다. 제품 리스크는 실제 고객 질문으로
품질·시간 절감·지불 의사를 독립 비교한 PoC가 없다는 점입니다. 운영·제한 자율성·Devnet
증거가 통과해도 시장 수요나 Mainnet 상용 준비를 증명하지는 않습니다. Rust mutation
survivor 221개도 Mainnet 전 우선순위별로 줄여야 합니다.

## 리허설 합격 기준

1. 세 번 연속 5분 45초 이내에 끝난다.
2. 발표자는 슬라이드를 읽지 않고 각 장의 한 문장 주장만 말한다.
3. 라이브 데모를 성공 경로, 네트워크 지연, 증거 미준비의 세 경우로 각각 연습한다.
4. 12초 중단 기준을 지키며 동일 결제를 임의로 다시 실행하지 않는다.
5. 질의응답에서 A2A·multi-agent·AP2·Passkey·embedded wallet·onramp·Mainnet·온체인 escrow program을 구현했다고
   주장하지 않는다.
6. 발표 직전 검증 명령의 구성 게이트가 통과하고, 라이브 주장을 하려면 live gate도
   통과한다.

```bash
npm run pitch:verify
npm run pitch:verify-live
```

`pitch:verify`는 슬라이드 순서, 문구 drift, 로컬 자산, 24개 MCP 도구와 런북 필수
구성만 검사한다. 362개 전체 테스트를 다시 실행하거나 실제 발표 시간을 재거나
내용의 진실성을 독립적으로 판정하지 않는다. `pitch:verify-live`는 공개 네트워크와
두 단계 Vertex 증거 구조까지 확인하지만 운영·AI·온체인 판정은 별도 수집기가 만든
세 evidence JSON에 의존한다. 발표 시간은 세 번의 실제 리허설로
검증한다.

## 10분 버전

시간이 10분으로 늘어나면 `6`을 눌러 전체 덱으로 전환하고 본편에 다음 네 장을
추가한다.

- 제품 해결책 뒤: `질문이 공급을 만드는 선순환`
- Gemini 전에: `검색과 랭킹`
- 결제 뒤: `제한된 자동결제`, `CLI와 MCP`
- 목표 고객 뒤: `경쟁 우위와 6주 도입 계획`

시장 규모, 단위경제와 3개년 시나리오는 본편보다 질의응답에 둔다. 실제 PoC 데이터가
없는 성장 가정을 길게 설명하는 것보다, 검색·결제·복구의 연결 증거를 더 오래 보여주는
편이 이 심사 기준에 강하다.
