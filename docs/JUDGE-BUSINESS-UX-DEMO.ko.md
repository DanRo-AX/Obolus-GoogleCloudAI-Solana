# Obulus 비즈니스·UX 심사 증거 카드

기준일: 2026-08-11<br>
대상: 비즈니스 가치 및 UX 30%, 라이브 데모 보조<br>
정본 발표 진행: [`FINAL-PITCH-RUNBOOK.ko.md`](./FINAL-PITCH-RUNBOOK.ko.md)

## 문서 소유와 완료 기준

worker-2가 `/coverage`의 가치 흐름과 이 증거 카드를 구현·검증한다. 발표 전담 워커는
정본 덱과 발표 런북에 필요한 문장만 가져간다. 덱 자체는 이 문서의 변경 대상이 아니다.

다음이 모두 충족되면 이 범위가 끝난다.

1. `/coverage`에서 구매자·기여자·프로토콜 가치가 실제 `orders` 상태와 함께 보인다.
2. 세 행동 링크가 질문 화면(`/`), 공개 모집(`/dashboard`), 영수증(`/archive`)으로 간다.
3. 한국어·영어, 375·768·1024·1440px, 키보드 포커스와 44px 터치 영역을 확인한다.
4. web build와 lint, gateway mutation 200/200 kill이 통과한다. Rust 전체 mutation은
   437개 중 221개 survivor 기준선을 숨기지 않고 후속 backlog로 관리한다.
5. 실제 운영·Devnet 주장은 아래 증거 게이트를 통과한 경우에만 사용한다.

## 30초 핵심 주장

> Obulus는 답변을 생성해서 파는 서비스가 아니다. 질문자는 검색 메타데이터를 무료로
> 비교하고 필요한 인간 근거만 문서당 ₩5~₩25에 연다. 채택된 답변은 버전이 있는 문서가
> 되어 조건에 맞게 다시 열릴 때마다 소유자에게 90%가 정산된다. 표시 가격에 포함된
> 10%만 프로토콜 매출이 되므로, 매출은 실제 근거 전달과 함께 발생한다.

이 주장을 첫 화면의 정적인 숫자로 입증하지 않는다. `/coverage`의
`하나의 시장, 세 가지 증명`에서 다음 세 행동으로 이동해 실제 흐름을 보여준다.

| 역할 | 제품에서 보이는 가치 | 바로 실행할 화면 | 구현 근거 |
| --- | --- | --- | --- |
| 구매자 | 무료 메타데이터 검색 후 필요한 문서만 결제. 근거가 없으면 답을 지어내지 않고 대상이 분명한 공개 모집으로 전환 | `/`의 `질문 실행` | `src/pages/Coverage.tsx`, `src/pages/Chat.tsx` |
| 기여자 | 한 번 채택된 답변이 문서가 되고, 조건에 맞는 재열람마다 90% 정산 | `/dashboard`의 `공개 모집 찾기` | `src/pages/Coverage.tsx`, `src/pages/Memory.tsx` |
| 프로토콜 | 표시 가격에 포함된 10%를 전달 완료 시점에만 인식. 구독료와 결제 단계 추가금 없음 | `/archive`의 `영수증 확인` | `src/lib/pricingPolicy.ts`, `src/pages/Archive.tsx` |

## 45초 라이브 데모

### 0–12초: 시장의 양면을 한 화면에서 고정

1. `/coverage`를 연다.
2. `남은 자리`와 `대기 중` 금액을 읽되, 시드나 샌드박스 실행이면 그 상태를 먼저 밝힌다.
3. `하나의 시장, 세 가지 증명`까지 스크롤한다.

말할 문장:

> 같은 질문 흐름이 세 가지 가치를 만듭니다. 질문자는 필요한 근거만 사고, 기여자는
> 같은 경험으로 다시 벌고, Obulus는 근거가 실제로 전달될 때만 수익을 얻습니다.

### 12–27초: 구매자 비용과 실패 UX

`질문 실행`을 눌러 질문 화면(`/`)으로 이동한다. HIT이면 무료 후보 비교와 정확한 총액을,
MISS이면 필요한 대상·답변 수·제안 보상이 있는 공개 모집을 보여준다.

리허설의 HIT 질문은 목업 백엔드가 명시적으로 보장하는 성수·평일·점심·비용 맥락을
사용한다. 라이브 무대에서 MISS까지 새로 만들지 않는다. MISS UX는 이미 열린
`/coverage`의 부족 분야와 공개 모집으로 설명한다.

말할 문장:

> 검색 실패를 AI가 꾸며낸 답으로 덮지 않습니다. 기존 근거가 있으면 필요한 문서만
> 열고, 없으면 누구의 경험이 몇 건 필요한지 공개합니다.

### 27–38초: 기여자 재수익

`/dashboard`에서 실제 공개 모집 한 건을 짚고 `/memory`의 자동 매칭과 수익 원장을
보여준다. 새 답변을 매번 요구하지 않고, 기존 문서가 실제로 다시 열릴 때만 수익이
생긴다는 점을 말한다.

`/dashboard`에서 `/memory`로는 왼쪽 사이드바의 `내 서가`를 누른다. 모집이 0건이면
임의 데이터를 추가하지 않고 `/coverage`의 0 상태를 보여준 뒤 정본 런북의 증거 장으로
전환한다.

### 38–45초: 매출과 검증 가능성

`/archive`에서 질문·열린 문서·금액·Explorer 링크가 한 영수증으로 묶이는 것을
보여준다. 아직 실제 거래가 없다면 빈 상태를 억지로 채우지 않고 아래 증거 게이트로
전환한다.

## 라이브 주장 게이트

- `artifacts/finalist-evidence/infrastructure.json`과
  `artifacts/finalist-evidence/devnet.json`이 모두 존재하고 각각
  `summary.ready=true`일 때만 현재 운영 경로와 실제 Devnet 지급을 함께 검증했다고
  말한다.
- `node scripts/verify-pitch-readiness.mjs --require-live`가 통과해도 파일의
  `generatedAt`, 현재 서빙 revision, 데모 job ID와 transaction signature가 같은
  리허설 실행을 가리키는지 직접 확인한다. 오래된 `ready=true`는 현재 증거가 아니다.
- 목업 백엔드 실행은 제품 UX 리허설 근거다. 온체인 결제 근거가 아니다.
- fixture signature, 샌드박스 receipt, 과거의 무관한 Explorer 거래를 현재 라이브
  근거처럼 사용하지 않는다.
- 한 단계가 12초 넘게 멈추면 결제를 반복하지 않는다. 덱에서 `B`를 눌러 정본 발표
  런북의 마지막 증거 장으로 전환하고 통과한 범위만 말한다.
- 질문에는 개인식별정보나 민감정보를 넣지 않는다. 유료 구절은 제품의 권한 경계 안에서만
  보여주고 원시 API 응답이나 제출용 JSON에 복사하지 않는다.

## 심사위원에게 보여줄 비즈니스 지표

실제 PoC 전에는 시장 크기나 전환율을 만들어내지 않는다. 다음 지표의 정의와 계측
위치만 제시하고, 실제 실행에서 얻은 값만 채운다.

| 지표 | 정의 | 왜 중요한가 | 시스템 근거 | 독립 검증 |
| --- | --- | --- | --- | --- |
| HIT rate | 질문 중 기존 인간 문서 최소 묶음으로 답한 비율 | 기존 조사 재사용 가치 | query decision, liquidity state | 사전 등록한 실제 고객 질문을 블라인드 적합성 평가 |
| Time to evidence | 질문 제출부터 첫 결제 근거 공개까지 걸린 시간 | 구매자 시간 절감 | query/job/settlement timestamp | 같은 팀의 기존 조사 방식과 시작·종료 기준을 맞춘 비교 |
| Paid documents per query | 한 질문에서 실제로 열린 독립 문서 수 | 과잉 구매 방지와 답변 다양성 | quote와 receipt | transaction signature와 수취인 잔액 변화 대조 |
| Contributor reuse rate | 채택 문서 중 새 답변 없이 다시 열린 비율 | 공급자의 반복 수익 | memory access와 earnings ledger | 소유자 지갑의 지급 receipt와 재열람 원문 ID 대조 |
| Recovery rate | 결제 응답 유실·재시도 중 복구 완료 비율 | 자동 결제 신뢰 | payment attempt와 refund claim | 장애 주입 후 두 독립 RPC의 finalized 거래·환불 재현 |
| Duplicate settlement | 동일 job 재시도에서 추가 지급된 수 | 비용 통제 | payment attempt ledger | 같은 job 반복 후 두 독립 RPC와 수취인 잔액에서 추가 지급 0 확인 |

내부 원장이 스스로 만든 성공 상태만으로 비즈니스 가치를 판정하지 않는다. 시간 절감과
근거 적합성은 고객의 기존 업무 기준선과 블라인드 평가가 필요하고, 결제·복구는 원장
밖의 RPC receipt와 지갑 잔액 변화가 들어와야 통과다.

PoC를 시작하기 전에 지표 사전을 고정한다. HIT rate의 분모는 사전 등록한 고유 고객
질문, 분자는 결제된 인간 근거가 실제 화면에 전달된 질문이다. Time to evidence는 클라이언트가
질문 제출을 수락한 시점부터 finalized 결제 근거가 처음 렌더된 시점까지다. 독립 문서는
content hash와 소유자가 모두 다른 문서로 센다. Duplicate settlement의 단위는
`job ID + quote ID + recipient`이며 한 번을 넘으면 즉시 실패다.

## 발표 전 UX 점검

```bash
npm run build:web
npm run lint -- src/pages/Coverage.tsx src/i18n/ko.ts
npm --prefix payment-gateway run test:mutation
# Rust 전체 mutation은 고비용 수동/예약 실행이며 현재 pass gate가 아니다.
# 최신 기준선: 437 total / 197 caught / 221 missed / 19 unviable.
```

UX 리허설은 저장소 루트에서 터미널 두 개를 유지한다. 첫 터미널의
`npm run demo:mock`이 `listening on http://127.0.0.1:8787`을, 둘째 터미널의
`npm run dev -- --host 127.0.0.1`이 Local URL을 출력한 뒤 브라우저를 연다. 이 경로는
샌드박스 원장과 시드 데이터이며 온체인 증거가 아니다.

브라우저에서 `/coverage`를 열고 다음을 확인한다.

1. 한국어와 영어에서 세 역할 제목·본문·행동 링크가 모두 보인다.
2. `질문 실행`, `공개 모집 찾기`, `영수증 확인`이 각각 `/`, `/dashboard`,
   `/archive`로 이동한다.
3. 375, 768, 1024, 1440px에서 가로 스크롤이 생기지 않는다.
4. 링크는 키보드 포커스가 보이고 최소 44px 높이의 터치 영역을 가진다.
5. 화면에 표시되는 모집 건수·남은 자리·예산은 `useUi().orders`에서 계산되며,
   정적인 성과 숫자가 아니다.

## 발표자료에 옮길 한 장 분량

제목: `하나의 시장, 세 가지 증명`

- 구매자: 검색 무료, 필요한 인간 근거만 문서당 결제
- 기여자: 한 번 쓴 답변이 조건부 반복 수익 자산으로 전환
- 네트워크: 전달 완료된 열람료의 포함 수수료 10%

하단 증거 줄:

`질문 → 최소 근거 선택 → 결제된 원문 → 영수증 → 소유자 수익`

이 장에 TAM, 가상 고객 수, 추정 전환율을 넣지 않는다. 실제 제품 딥링크와 원장
receipt가 같은 이야기를 증명하게 한다.
