Rust authoritative core

클라이언트가 보낸 userId나 eligibility를 신뢰하지 않고 세션과 서버 프로필로 다시 계산한다.

SQLite transaction boundary

오픈콜 예약, 답변 지급, 분쟁 승인, 취소 환불, 계정 삭제는 각각 하나의 트랜잭션으로 원자 처리된다.

Payment boundary

문서 열기는 실제 Devnet USDC로 정산된다. 게이트웨이가 동적 quote와 x402를 처리하고, 실패한 Rust 원장 mirror는 outbox에서 재시도한다.

AI liquidity boundary

Gemini는 일반 Baseline과 인터뷰 질문만 공급한다. AI 산출물은 documents, Memory, authority, 정산에 들어가지 않고 인간 공급이 충분하면 Baseline 호출 자체가 차단된다.

HTTP boundary

api.rs

Axum 라우팅, 쿠키 세션, 인증·관리자 권한, 오류 응답.

Business state

store.rs

SQLite 스키마, 마이그레이션, ACID 정산과 도메인 불변식.

Retrieval

search.rs

문서 후보, 타깃 필터, 예산, HIT/MISS 및 안전한 quote.

AI liquidity

orchestrator.rs

일반 Baseline, 기여자 인터뷰 질문, 결제된 인간 증거 종합의 서로 다른 경계.

Enforcement

quality.rs

구체성·길이·질문 반복 검증과 voided 판정.

Logical user references managed by Rust transactions: open_calls.owner_id, memory_entries.user_id, funding_events.user_id, earning_events.author_id → users.id. These remain non-FK so account deletion can anonymize audit rows without erasing financial history.

한 사람, 한 오픈콜 답변 memory_entries(open_call_id, user_id) 부분 UNIQUE 인덱스.
한 사람, 한 번의 분쟁 dispute_events.user_id가 PK라 계정별 1회만 허용.
중복 지급 차단 earning_events(settlement_id, document_id) UNIQUE 인덱스.
잔액 음수 금지 available, reserved, held에 CHECK ≥ 0과 조건부 UPDATE 적용.
익명 삭제 개인 데이터는 삭제하고 금융·정산 감사행의 사용자 ID는 치환.
문서는 지급 후 공개 검색 응답은 handle과 가격만 제공하고 본문은 settlement 뒤 반환.
AI는 시장 자산이 아님 ai_baselines와 shelf_starters는 documents와 분리되며 인간 답변만 문서화.
온체인 중복 정산 차단 quote_id와 transaction_signature UNIQUE, 수취인·network·atomic amount 완전 일치.
검증된 저자에게만 지급 Ed25519 서명 완료 지갑만 payout에 사용하고 주소 변경 시 검증을 폐기.

핵심 트랜잭션

요청 하나가 어떤 테이블을 바꾸고, 실패했을 때 무엇이 그대로 남아야 하는지를 사용자 시나리오별로 표시한다.

01 · Retrieval

검색 HIT → 유료 문서 열기

  1. 01
    안전한 검색

    locked 본문 없이 handle, score, 가격, 인구통계만 반환.

  2. 02
    Quote·복구 권한 고정

    순위와 가격, 해시된 payment access token을 기록.

  3. 03
    한 번의 동적 x402 결제

    문서 1개는 저자에게 직접, 2개 이상은 정확한 bundle hash·총액으로 에스크로에 한 번 결제하고 facilitator가 서명과 정산을 검증.

  4. 04
    본문·온체인 영수증·저자 claim

    정산을 idempotent하게 mirror하고 문서별 수익자를 claimable로 기록하며 응답 손실 시 payer별 상태와 본문을 복구.

02 · Commission

검색 MISS → 오픈콜 에스크로

  1. 01
    전체 예산 예약

    available에서 unit price × target을 빼고 reserved에 더한다.

  2. 02
    타깃 자격 판정

    category + age + region + household + field를 서버 프로필과 AND 비교.

  3. 03
    인터뷰·답변 원자 저장

    워밍업 문답은 비공개 memory context로 보존하고 최종 유료 답변만 searchable document로 만든다. voided이면 슬롯·문서·지급은 모두 0.

  4. 04
    단위 지급 또는 환불

    답변당 reserved 한 단위를 지급하고, 취소 시 남은 escrow만 구매자에게 환불.

03 · Enforcement

Voided 답변 → 관리자 분쟁

  1. 01
    Pending 생성

    서면 사유를 저장하되 strike, 슬롯, 지급은 바꾸지 않는다.

  2. 02
    관리자만 심사

    세션 role=admin과 필수 reviewer rationale를 검증.

  3. 03A
    승인

    문서 복원, 슬롯 증가, escrow 감소, 기여자 지급을 한 트랜잭션으로 처리.

  4. 03B
    기각

    답변은 voided, escrow는 예약 상태, 지급은 0으로 유지.

04 · Privacy

계정 삭제 → 감사 가능한 익명화

  1. 01
    오픈 예약 정리

    소유한 open call을 취소하고 unused escrow를 먼저 환불.

  2. 02
    개인 본문 삭제

    query reference, documents, memory, profile과 wallet 연결 제거.

  3. 03
    금융행 익명화

    open_calls, funding, earning audit ID를 deleted:* 식별자로 치환.

  4. 04
    접근 폐기

    sessions, balance, users를 삭제해 기존 쿠키와 비밀번호 로그인을 모두 차단.

도메인 백엔드는 Rust, x402 SDK 경계는 TypeScript

검색·권한·가격·원장·본문 공개 규칙은 Rust가 소유한다. 공식 x402 SVM SDK가 제공되는 얇은 HTTP 결제 경계만 TypeScript로 두었다.

현재 Rust가 소유하는 영역

  • axumREST API, 미들웨어, 쿠키와 관리자 권한
  • tokio비동기 서버, shutdown, 향후 background worker
  • rusqlite스키마, 마이그레이션, 트랜잭션과 원장
  • argon2비밀번호 해시와 세션 인증
  • search.rs검색·랭킹·예산·타깃 필터·HIT/MISS
  • quality.rs답변 품질, strike와 dispute 진입 판정

프로덕션에서도 Rust로 확장할 영역

  • @x402/svmTypeScript gateway의 공식 exact/SVM 검증·정산 계약
  • reqwest이메일, KMS, 외부 정책 API를 호출할 Rust worker
  • sqlxPostgreSQL 전환과 async connection pool
  • towerrate limit, timeout, request ID, tracing
  • opentelemetry메트릭, trace, 정산 reconciliation 관측
  • object store암호화 백업과 문서 blob 분리
